# Ripple App Store Release Assets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a debug-only deterministic data fixture and a reusable App Store marketing-asset workflow that produces, validates, and uploads polished English and German iPhone/iPad screenshots.

**Architecture:** The iOS composition root recognizes `-ripple-demo-data` only in `DEBUG`, waits behind `DemoDataGateView`, and calls a `RippleData` seeder that uses existing `UseCases`. A personal `app-store-release-assets` skill consumes a release manifest and real simulator captures, composes opaque device-framed advertisements with Pillow, validates exact Apple dimensions, and hands the reviewed sets to `asc`.

**Tech Stack:** Swift 6.2, SwiftUI, SwiftData, `@ModelActor`, Swift Testing, Xcode/simctl, Python 3 + Pillow, App Store Connect CLI (`asc`), San Francisco/system fonts.

**Spec:** `Docs/superpowers/specs/2026-09-05-app-store-release-assets-design.md`

## Global Constraints

- Use Swift and SwiftUI only for app changes; keep Swift 6 strict concurrency enabled.
- Use `@Observable`/`@MainActor` patterns already present in the app; do not add `ObservableObject` or Combine view state.
- Every intake must go through `LogIntake.run(amount:source:date:)`; the fixture may only use its optional fixture ID extension.
- Persist through existing repositories and `RippleStore @ModelActor`; do not add `@Query` writes, direct model-context writes from views, or UserDefaults storage.
- Keep all domain amounts as integer milliliters and use existing `UnitConverter` behavior.
- Keep the launch flag and gate in `Apps/RippleiOS`; do not add fixture branching to feature view models or domain rules.
- Without `-ripple-demo-data`, runtime behavior must remain unchanged; no shipped UI may expose demo generation or deletion.
- Support `en-US` and `de-DE`; German UI and marketing copy must not fall back to English hardcodes in the final assets.
- Use only `#0B3D4A`, `#1A7A8C`, `#4FB3C6`, `#E8F4F6`, opacity variants, and neutral device surfaces for marketing compositions; do not use purple or orange.
- Use San Francisco/system typography, 4-point-aligned layout values, 20/28-point card/hero radii, and restrained shadows.
- Export opaque JPEGs at 1320×2868 for iPhone 6.9-inch and 2064×2752 for iPad 12.9-inch.
- Keep metadata and all screenshot inputs/outputs below `release/`; preserve unrelated dirty worktree changes.
- Do not perform remote App Store Connect replacement until local visual review and a dry run are complete; replacement uses explicit `--confirm`.
